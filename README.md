# tgbup

Архив ваших чатов, групп и форумов Telegram на этом Mac. Сообщения хранятся в базе SQLite, файлы лежат рядом.
Архив можно читать в браузере и в Obsidian, файлы с понятными именами лежат в одной папке. Обновляется сам 4 раза в день, зашифрованные бэкапы
уходят во все выбранные места.

- **Только читает Telegram.** Каждый вызов проверяется по белому списку, отправить, изменить или удалить что-либо
  в аккаунте tgbup не может (см. [«Что tgbup делает в Telegram»](#что-tgbup-делает-в-telegram)).
- **Ничего не удаляет.** Сообщения, удалённые в Telegram, остаются в архиве. Восстановление из бэкапа не затирает
  то, что уже лежит на диске.
- **Всё на этом Mac.** Страница управления открывается только с этого компьютера. Пароли и ключи лежат в файле
  с правами 600.

Как устроено внутри (подсистемы, раскладка на диске) и журнал решений — [`docs/PROJECT.md`](docs/PROJECT.md).

## Быстрый старт

Что понадобится: телефон с Telegram (для кода входа) и минут 10–15 на настройку. Первая выгрузка может идти дольше, если в чатах много медиа.

```bash
brew install go
```

```bash
make setup
```

`make setup` соберёт tgbup, поставит его в `~/.local/bin/tgbup` и откроет страницу настройки в браузере. Если
удобнее в терминале, `make setup-cli` запустит те же шаги (`tgbup init`).

## Настройка по шагам

Страница настройки и `tgbup init` проходят одни и те же шаги. Сделанные отмечены галочкой и повторно не
спрашиваются. Прервать можно в любой момент: повторный `make setup` или `tgbup init` продолжит с того же места.
Тем же путём потом меняются чаты, места бэкапа, ключи и пароль.

| # | Шаг | Что делаете вы |
|---|---|---|
| 1 | Ключи Telegram | на https://my.telegram.org → API development tools создаёте приложение, вставляете `api_id` и `api_hash` |
| 2 | Вход | телефон → код из приложения Telegram → пароль двухэтапной проверки, если он есть |
| 3 | Папка архива | по умолчанию `~/TelegramArchive` (кнопка «Choose…» открывает окно выбора папки). **Или** «Restore from a backup», см. [«Восстановление»](#восстановление) |
| 4 | Чаты | отмечаете чаты, папки Telegram и топики форумов (см. [«Выбор чатов»](#выбор-чатов)) |
| 5 | Бэкапы | папка на этом Mac (по умолчанию `~/TelegramBackup`) и дополнительные места; пароль |
| 6 | Бот для уведомлений (необязательно) | создаёте бота у @BotFather, вставляете токен, пишете боту — chat_id tgbup найдёт сам и пришлёт проверочное сообщение |
| 7 | Первая выгрузка | Telegram пришлёт запрос на экспорт данных — разрешите его в приложении. Можно и без экспорта, тогда выгрузка будет медленнее |
| 8 | Расписание | ставит запуск в 00:30, 06:30, 12:30, 18:30 и делает проверочный запуск. Заодно macOS спросит доступ к iCloud, если он выбран |
| 9 | `PATH` (только в терминале) | добавляет `~/.local/bin` в профиль shell, чтобы команда `tgbup` работала везде |

**Пароль бэкапов** никогда не задаётся молча: tgbup генерирует его и показывает («Use this password?»), или вы
вводите свой дважды. Где хранить копию, решаете вы. Без этого пароля бэкапы не открыть, восстановить его невозможно,
а на этом Mac он лежит в `secrets.env`, который в бэкап не входит. На новом Mac выберите «ввести свой» и введите
прежний.

**Места бэкапа.** Снимок делается во все выбранные места при каждом запуске:
- папка на этом Mac — по умолчанию `~/TelegramBackup`, можно выбрать другую или отказаться;
- найденные tgbup: iCloud Drive, Google Drive, Dropbox и OneDrive из `~/Library/CloudStorage`, внешние диски
  из `/Volumes`;
- Google Drive без приложения — через rclone, вход в браузере (доступ только к файлам, созданным tgbup);
- любой свой путь или restic-репозиторий.

Папку iCloud в Finder стоит пометить «Всегда хранить на этом Mac». Бэкап можно и выключить: шаг «Backups» →
«Keep backing up? n». Уже сделанные снимки останутся.

Ключи, пароль бэкапов и токен бота хранятся в `~/.config/tgbup/secrets.env` (права 600), настройки — в
`~/.config/tgbup/config.yaml`.

## Как это работает дальше

Расписание запускает `tgbup run` 4 раза в день. Если Mac спал, пропущенный запуск сработает после пробуждения.
Запуск делает следующее:
1. скачивает новые сообщения и медиа;
2. перерисовывает изменившиеся страницы архива;
3. делает снимок во все места бэкапа — даже если выгрузка не удалась;
4. сообщает через бота: об ошибках сразу, сводку раз в 7 дней (`notify.summary_every`).

Посмотреть, как дела, — `tgbup serve --open`. Страница http://localhost:8640 открывается только с этого Mac:
- **обзор** — последний запуск и его ошибки, размер архива, время последнего снимка в каждом месте, расписание.
  Кнопка «Update now» запускает то же, что расписание, и показывает журнал;
- **Setup** — все шаги настройки и восстановление;
- **Chats** — выбор чатов и топиков;
- **Archive** — архив как сайт, на соседнем порту (http://localhost:8641). Порт отдельный, чтобы присланные
  в чатах файлы не имели доступа к странице управления.

Запуск со страницы идёт отдельным процессом: закрытие страницы его не прервёт. Два запуска одновременно не
идут: если один уже работает, второй пропускается.

Журнал запусков: `~/.local/state/tgbup/logs/run.log`. Что делает страница (каждое действие, ошибки, запуски
выгрузки, медленные запросы), пишется в терминал, где запущен `tgbup serve` или `make setup`; введённые пароли, коды
и токены туда не попадают. Состояние расписания: `tgbup schedule status`.

## Чтение архива

В папке архива (`~/TelegramArchive`):

| Что | Как читать |
|---|---|
| `html/index.html` | в браузере: список чатов и поиск по всему архиву. Чат (у форума — каждый топик) открывается на последней странице, по 500 сообщений на странице. «Jump to date» — переход к нужному дню. Фото, видео, голосовые, файлы, превью ссылок, места, опросы — прямо в ленте |
| `html/media.html` | все фото, видео, файлы, голосовые, ссылки, места, контакты и опросы с фильтрами по типу, чату, топику, периоду и названию. Фильтры сохраняются в адресе, их можно добавить в закладки |
| `md/` | те же страницы в Markdown. Папку `~/TelegramArchive` можно открыть как хранилище Obsidian |
| `media/` | сами файлы, по году: `media/2025/2025-06-14_180233_Договор аренды.pdf`. После даты — оригинальное имя файла; у фото, голосовых и кружков его нет, тогда название чата. Сортировка по имени — по времени, дата изменения файла — дата сообщения. Из какого файл чата и сообщения, знают база и страницы |

Отправить чат кому-то: `tgbup export Family -o family.zip`. Получится zip со страницами и медиа, который
открывается двойным кликом по `index.html`. Чат можно указать названием или его однозначной частью, `@username`
или ID. Сузить выгрузку: `--topic Expenses`, `--from 2026-01 --to 2026-03`, `--no-media`.

Каждый файл лежит один раз, даже если его пересылали в несколько чатов. Имя задаётся при скачивании и потом не
меняется. Из оригинального имени убираются только символы, недопустимые в именах файлов; к расширениям, которые
запускаются двойным кликом (`.command`, `.sh`, `.pkg`, `.dmg`…), дописывается `.txt`. Чужим файлам ставится отметка
macOS о скачивании из интернета: при попытке запустить такой файл macOS переспросит. Свои файлы (отправленные вами,
не пересланные) без отметки. Переименовывать файлы в `media/` не стоит: страницы ссылаются на их имена.

`html/` и `md/` перерисовываются из базы, их можно удалить. Вручную, без Telegram: `tgbup render` (`--full` — всё
заново). После переименования чата в `html/` и `md/` остаётся старая папка: её можно удалить.

## Выбор чатов

Шаг 4 мастера, вкладка Chats или `tgbup setup` в терминале. Чаты сгруппированы: All chats, папки Telegram,
No folder, Archived. В терминале:
- списки идут по 20 на странице, листать `>`/`<`/`p N`;
- номера сквозные, можно `21-23,45`;
- `a`/`n` отмечают страницу, `A`/`N` — весь список;
- `s` — поиск по названию или `@username`;
- `t N` открывает топики форума. Снятая отметка исключает топик, новые топики архивируются автоматически;
- `d` показывает подробный отчёт, затем итоговый конфиг и спрашивает, записать ли его;
- команды понимаются и в русской раскладке.

Проверить, что будет выгружено, ничего не скачивая: `tgbup sync --dry-run`.
```
would archive 2 chats, ~17 062 messages:
── 1. Family · forum · -1002263466511 ─────────────────────────────
   ~4 812 msgs: photos 310 · videos 42 · files 18 · voice 97 · round 12 · links 55
   topics 5 of 7:  General #1 ~1 200 · Recipes #3 ~300 · …
   excluded:       Flood #5 ~2 900 · Memes #12 ~150   (~3 050 msgs not saved)
── 2. Mom · private · 123456789 ───────────────────────────────────
   ~15 300 msgs: photos 1 204 · videos 80 · files 140 · voice 630 · links 210
══ Total: 2 chats, ~17 062 msgs saved · …
```

Конфиг можно править и руками. В конце файла есть закомментированная справка по всем настройкам.
```yaml
archive_dir: ~/TelegramArchive
targets:
  folders: ["Семья", "Бизнес"]   # папки Telegram
  include: ["@some_group"]        # плюс отдельные чаты; надёжнее числовые ID: username могут сменить
  exclude: []
  exclude_topics:                 # форум → ID топиков (видны в dry-run как «#5»)
    -1002263466511: [5, 12]
```
Если чат из `include` не найден, выгрузка завершается с ошибкой, чтобы архивирование не прекратилось молча.
Если вернуть исключённый топик, следующая выгрузка один раз перечитает историю форума и допишет пропущенное.

## Бэкапы

В снимок входят копия базы (проверенная `integrity_check`), `config.yaml`, `media/` и `html/` — страницы, чтобы
архив из снимка можно было читать и без tgbup. Не входят:
- `md/` — то же, что `html/`;
- сессия Telegram и `secrets.env` — на новом Mac вход делается заново.

Хранятся 4 последних снимка, 7 дневных, 4 недельных и 12 месячных. Лишние удаляются раз в сутки, проверка 5% данных
идёт раз в 30 дней. Снимок вручную: `tgbup backup`.

Бэкапы делает [restic](https://restic.net), Google Drive без приложения подключается через
[rclone](https://rclone.org). Ставить их не нужно: tgbup скачивает нужные версии сам и сверяет контрольные суммы
(`tgbup deps` показывает, где они лежат).

## Восстановление

На новом Mac или после потери архива:
1. `make setup`, ключи Telegram и вход — как при первой настройке.
2. Шаг «Archive folder» → «Restore from a backup». В терминале — ответ `y` на «Restore an archive from an existing
   backup» или отдельная команда `tgbup restore`.
3. Указать место бэкапа и пароль, выбрать снимок (по умолчанию последний).
4. Дальше мастер продолжит обычные шаги. Чаты уже выбраны, если конфиг взят из снимка.

Google Drive через rclone на новом Mac подключается заново, входом в браузере.

Что происходит при восстановлении:
- **база** — если в папке архива уже есть `archive.sqlite`, её переименовывают в
  `archive.sqlite.before-restore-<время>`, а восстановленная встаёт на её место;
- **медиа** — недостающие добавляются, такие же остаются. Если под тем же именем лежит другой файл, он
  переносится в `media.before-restore-<время>`, а на его место встаёт файл из снимка: на него ссылается
  восстановленная база;
- **конфиг** — берётся из снимка, если в текущем ещё не выбраны чаты. Тогда места бэкапа из обоих
  объединяются. Конфиг с выбранными чатами не меняется;
- **пароль** — сохраняется, только если своего ещё нет. Если у вас уже другой пароль, он остаётся, а место, из
  которого восстанавливали, в бэкапы не добавляется: один пароль должен открывать все места;
- **страницы** перерисовываются.

Свободного места нужно на снимок целиком: он сначала раскладывается во временную папку рядом с архивом, а потом
переносится переименованием.

`tgbup restore` в терминале:
- `--from <место>` — откуда восстанавливать (иначе — первое место из конфига или вопрос);
- `--snapshot <id|latest>` — какой снимок;
- `--to <папка>` — куда;
- `--list` — только показать снимки.

<details>
<summary>Без tgbup (например, на другой ОС)</summary>

1. Поставить restic. Для Google Drive ещё rclone и заново `rclone config` с тем же именем хранилища (`gdrive`).
2. Восстановить последний снимок:
   ```bash
   RESTIC_PASSWORD=… restic -r "<репозиторий>" restore latest --target ~/restore
   ```
   Пути в снимке абсолютные: в `~/restore` окажутся `…/.local/state/tgbup/backup/archive.sqlite`,
   `…/config.yaml`, `…/TelegramArchive/media/` и `…/TelegramArchive/html/`.
3. Чтобы только почитать, достаточно открыть `…/TelegramArchive/html/index.html`.
4. Чтобы продолжить архив: `archive.sqlite` и `media/` положить в папку архива, `config.yaml` — в
   `~/.config/tgbup/`, `secrets.env` создать заново, затем `tgbup login` и `tgbup render`.
</details>

## Что tgbup делает в Telegram

Только читает. Каждый вызов Telegram API проходит через белый список методов (`internal/tgclient/readonly.go`).
Всё, чего в списке нет, отклоняется до отправки в сеть: отправка, правка, удаление, пересылка, отметка
«прочитано», реакции, вступление и выход из чатов, изменение профиля и настроек.

| Методы | Зачем |
|---|---|
| `messages.getDialogs`, `messages.getDialogFilters` | список чатов и папок |
| `messages.getHistory`, `messages.getReplies`, `messages.search`, `messages.getSearchCounters` | сообщения, их число, закрепы, счётчики по типам |
| `messages.getForumTopics` | топики форумов |
| `messages.getMessages`, `channels.getMessages` | перечитать сообщение для свежей ссылки на файл |
| `channels.getFullChannel` | из какой группы выросла супергруппа |
| `users.getUsers` | свой id, проверка входа |
| `upload.getFile` | скачивание медиа |
| `auth.sendCode`, `auth.signIn`, `account.getPassword`, `auth.checkPassword` | вход |
| `account.initTakeoutSession`, `account.finishTakeoutSession` | экспорт для первой выгрузки |
| `help.getConfig`, `help.getNearestDc`, `help.getCdnConfig`, `auth.exportAuthorization`, `auth.importAuthorization` | служебное соединение с дата-центрами |

Заметно в аккаунте только следующее:
- вход создаёт сеанс «tgbup» в списке активных сеансов, как любое приложение Telegram. Если её завершить, tgbup
  перестанет выгружать и сообщит об этом;
- экспорт данных Telegram подтверждает запросом в приложении.

История читается без отметки «прочитано», собеседники ничего не видят.

## Команды

| Команда | Что делает |
|---|---|
| `tgbup init` | настройка по шагам в терминале; повторный запуск продолжает или меняет настройки |
| `tgbup serve --open` | страница на этом Mac: настройка, обзор, «Update now», чаты, архив |
| `tgbup setup` | выбор чатов в терминале |
| `tgbup sync` | выгрузить новое (`--dry-run` — только показать, `--takeout` — через экспорт данных) |
| `tgbup run` | то, что запускает расписание: выгрузка, бэкап, уведомления |
| `tgbup backup` | снимок вручную (`--init` — создать хранилища) |
| `tgbup restore` | восстановить архив из бэкапа (`--from`, `--snapshot`, `--to`, `--list`) |
| `tgbup render` | перерисовать страницы без Telegram |
| `tgbup export <чат>` | zip с чатом, топиком или периодом |
| `tgbup schedule install\|status\|uninstall` | расписание launchd |
| `tgbup notify test` | проверочное сообщение от бота |
| `tgbup login` | войти в Telegram заново |
| `tgbup deps` | где лежат restic и rclone (скачает, если нет) |

## Если что-то не так

| Что видно | Что делать |
|---|---|
| «the Telegram session is no longer valid» | сессию завершили в Telegram: `tgbup init` (или `tgbup login`) |
| «another tgbup run is in progress» | идёт другой запуск (плановый или «Update now»), дождитесь его конца |
| Первая выгрузка ждёт разрешения | разрешите экспорт данных в приложении Telegram и нажмите Enter, или `s` — качать без экспорта |
| Чат из `include` не найден | его переименовали или вы из него вышли: поправьте список в Chats или `tgbup setup` |
| Бэкап в iCloud не делается | при проверочном запуске macOS спрашивала доступ к iCloud. Если отказали, разрешите в «Системные настройки» → «Конфиденциальность и безопасность» → «Файлы и папки» |
| Google Drive через rclone: нет доступа | шаг «Backups» → «Sign in to Google Drive again» |
| Забыт пароль бэкапов | старые снимки открыть нельзя. Задайте новый пароль и новое место бэкапа |
| Подробности любой ошибки | `~/.local/state/tgbup/logs/run.log` и обзор на странице `tgbup serve` |

## Разработка

```bash
make test         # юнит-тесты
make test-backup  # тесты бэкапа с настоящим restic
make lint
```

Тестовые серверы Telegram: `TGBUP_TEST_DC=1 bin/tgbup login` создаёт отдельную сессию `session-test`, боевая не
затрагивается. Всё остальное в этом режиме требует своих `TGBUP_CONFIG`, `TGBUP_SECRETS` и `TGBUP_STATE_DIR`
(скопируйте туда `session-test` и ключи API), иначе tgbup откажется запускаться. Это защищает от двух ошибок:
тестовые чаты не попадут в настоящий архив, а тестовый пароль бэкапа не заменит настоящий. Папки архива и бэкапа
по умолчанию в этом режиме лежат рядом с тестовым конфигом, расписание не ставится.

`make e2e` создаёт на тестовом аккаунте форум со всеми видами сообщений и прогоняет настоящий `tgbup sync`:
полную выгрузку, инкремент, dry-run, исключение и возврат топика. Затем проверяет архив и удаляет за собой форум
и папку. Писать в Telegram может только эта фикстура: её функция компилируется лишь с тегом `e2e`, работает только
на тестовых серверах и в бинарник `tgbup` не попадает.
