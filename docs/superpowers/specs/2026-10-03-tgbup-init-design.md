# tgbup: установка и настройка за один проход (`tgbup init`) — дизайн

Дата: 2026-10-03
Статус: реализован; изменения — в конце файла
решения приняты автономно (поручено пользователем)
Основа: `2026-10-02-tgbup-backup-design.md` (команды, конфиг, секреты в силе)

## 1. Цель

После `make setup` (сборка + установка + `tgbup init`) человек отвечает на
вопросы мастера и получает: ключи Telegram, вход, выбранные чаты, пароль
restic, созданные репозитории, бота, первую выгрузку и расписание с
проверочным запуском. Ни одного ручного редактирования файлов.

## 2. Решения

- **Одна команда `tgbup init`, повторяемая.** Каждый шаг сначала проверяет,
  сделан ли он; сделанный показывается строкой `✓ … — уже настроено` и не
  спрашивается (кроме чатов: «изменить? [y/N]»). Прерванный мастер (Ctrl+C)
  продолжается повторным `tgbup init` с первого несделанного шага. Всё, что
  записано, записано сразу (секреты и конфиг пишутся после каждого шага).
- **Ввод читается по запросу**, одним читателем на весь мастер: фоновое
  чтение stdin (как в `setup` сейчас) забирало бы строки и скрытый ввод
  пароля 2FA у входа в Telegram. `setup` переходит на тот же читатель.
- **Пароль restic генерируется** (крипто-случайный, ~150 бит, группы по 5
  символов), показывается один раз, на Mac копируется в буфер (`pbcopy`);
  шаг не завершится, пока человек не ответит, что сохранил его в менеджере
  паролей. Можно ввести свой.
- **Хранилища — меню с найденным на машине**: iCloud Drive (если есть),
  папки `~/Library/CloudStorage/*` (Google Drive, Dropbox, OneDrive как
  приложения), «Google Drive через rclone (вход в браузере)», «свой путь или
  репозиторий restic». По умолчанию: iCloud + Google Drive через rclone
  (не зависит от приложения Google Drive). Каталог в хранилище — `tgbup-restic`.
- **Google Drive через rclone без ручного `rclone config`**: если удалённого
  хранилища `gdrive` нет — `rclone config create gdrive drive scope=drive.file`
  (rclone сам открывает браузер для входа; доступ только к файлам, созданным
  rclone).
- **Бот: `chat_id` определяется сам.** Человек вставляет токен от
  @BotFather → `getMe` проверяет его и даёт имя бота → «напишите боту любое
  сообщение» → `getUpdates` (длинный опрос, до 3 минут) берёт первый личный
  чат, мастер показывает, от кого сообщение, и просит подтвердить → тестовое
  сообщение. Шаг можно пропустить (Enter).
- **Первая выгрузка** — только если в архиве ещё нет сообщений; через
  takeout. Если Telegram просит подтвердить экспорт — мастер объясняет, ждёт
  Enter и пробует снова (Ctrl+C — пропустить, расписание всё равно выгрузит
  обычным способом).
- **Расписание + проверочный запуск**: `schedule install`, затем
  `launchctl kickstart` и ожидание окончания запуска (опрос
  `launchctl print`, до 30 минут, Ctrl+C — перестать ждать) с итогом из
  `runs`/кода выхода и хвостом `run.log` при ошибке. Так сразу всплывает
  запрос macOS на доступ к iCloud/Google Drive.
- **PATH**: если каталога `tgbup` нет в `PATH` — предложить дописать
  `export PATH=…` в `~/.zprofile` (по согласию).
- **Скачиваемая установка без Go (релизы, `curl | sh`, Homebrew) — не
  сейчас**: репозиторий приватный; `make setup` требует только Go.

## 3. Шаги мастера

| # | Шаг | «Сделано», если |
|---|---|---|
| 1 | Ключи Telegram (`TG_API_ID`, `TG_API_HASH` с my.telegram.org; проверка: ID — число, hash — 32 hex) | оба есть |
| 2 | Вход в Telegram (тот же поток, что `login`) | сессия авторизована |
| 3 | Папка архива (по умолчанию `~/TelegramArchive`) — только при создании конфига | конфиг существует |
| 4 | Выбор чатов (диалог `setup`) | в конфиге есть targets → «изменить? [y/N]» |
| 5 | Пароль restic | `RESTIC_PASSWORD` есть |
| 6 | Хранилища | `backup.repositories` не пуст |
| 7 | Создание репозиториев (`backup --init`) + rclone/вход в Google Drive при необходимости | все репозитории отвечают `ready` |
| 8 | Бот (необязательно) | `BOT_TOKEN` и `BOT_CHAT_ID` есть |
| 9 | Первая выгрузка | в архиве есть сообщения |
| 10 | Расписание + проверочный запуск | задача установлена с этим же бинарником |
| 11 | PATH | каталог бинарника в `PATH` |

В конце — сводка: что настроено, где архив, как открыть (`html/index.html`),
где лог.

## 4. Запись файлов

- `secrets.env`: `config.SetSecrets(path, map)` — заменить или дописать
  `KEY=VALUE`, остальные строки и комментарии как были; атомарно, `0600`.
  Значения проверяются: без переводов строк.
- `config.yaml`: `config.SetValue(path, keys, value)` — правка YAML-дерева с
  сохранением комментариев (как `WriteTargets`), проверка до записи, справка
  по опциям при первой записи.

## 5. Тесты

- `SetSecrets`: замена, дописывание, сохранение комментариев, права 0600,
  отказ на значение с переводом строки.
- `SetValue`: создание файла, замена `backup.repositories` с сохранением
  комментариев и `targets`, отказ на невалидный конфиг.
- Читатель строк: последовательные запросы, EOF, Ctrl+C (ctx), длинная строка.
- Бот: `getMe`, `getUpdates` с фейковым Bot API (личный чат, пропуск групп,
  таймаут).
- Пароль: длина/алфавит; меню хранилищ: найденные папки, разбор выбора.
- Мастер целиком — с фейковыми шагами (Telegram, restic, launchctl):
  повторный запуск ничего не спрашивает у сделанных шагов; прерванный —
  продолжается с того же места.

## Расхождения с реализацией (сверка 2026-10-03)

- §3 Шагов 9, а не 11: пароль, места и создание репозиториев — один шаг «Backups» (по умолчанию включён:
  папка на этом Mac плюс дополнительные места; при повторном `init` репозитории проверяются). Пароль всегда
  генерируется и показывается (или вводится свой) и записывается только после `saved`.
- Ключи API и пароль бэкапа можно заменить («Enter different API keys?», «Replace the backup password?»).
- Отказ от бэкапа или бота (Enter в токене) показывается как `off`, а не как незаконченный шаг.
- При `TGBUP_TEST_DC=1` шаги расписания и `PATH` не выполняются: задача launchd одна и работает с
  боевым архивом.
- Проверочный запуск оценивается по записи в `runs`, а не по коду выхода launchd; если за 30 минут не
  закончился — шаг считается пропущенным.
- Google Drive через rclone: соединение проверяется (`rclone lsd`), при сломанном входе предлагается
  войти заново (`rclone config reconnect`).
