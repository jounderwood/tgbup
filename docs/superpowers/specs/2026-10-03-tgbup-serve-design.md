# tgbup serve: веб-интерфейс на этом Mac — дизайн

Дата: 2026-10-03
Статус: по запросу «давай сделаем serve»; решения приняты автономно (поручено
пользователем), пользователь проверит по возвращении
Основа: `2026-10-02-tgbup-backup-design.md` §2 (логика в пакетах, CLI тонкий;
`serve` вызывает те же пакеты, пересечение исключает `run.lock`)

## 1. Цель

Всё, что сейчас делается в терминале после установки, — в браузере:
посмотреть состояние (когда был последний запуск, всё ли хорошо с бэкапами),
запустить обновление сейчас, поменять список чатов и топиков, читать архив.
Первая настройка остаётся за `tgbup init` (вход в Telegram, пароли — в
терминале надёжнее).

## 2. Решения

- **Только этот Mac.** Слушает `127.0.0.1:8640` (`--listen` — другой порт или
  адрес, но только loopback: архив семейный и рабочий, без входа по паролю в
  сеть не выставляем; доступ с телефона — позже, с авторизацией).
- **Защита от чужих страниц в браузере:** заголовок `Host` должен быть
  `localhost`/`127.0.0.1`/`[::1]` с нашим портом (против DNS rebinding);
  каждый изменяющий запрос (POST) несёт токен процесса в заголовке
  `X-Tgbup-Token` (случайный, вшит в страницу; без cookie, поэтому чужой сайт
  его не получит и не отправит); CORS не включается.
- **«Обновить сейчас» = отдельный процесс `tgbup run`**, вывод дописывается в
  тот же `run.log`, что и у расписания. Так ручной и плановый запуски
  неотличимы, `run.lock` исключает пересечение, а закрытие страницы или
  `serve` не обрывает запуск. Идёт ли запуск — проверка `run.lock` (свой или
  плановый — всё равно).
- **Список чатов — тот же `selector`**, что и у `setup`: группы (All chats,
  папки Telegram, No folder, Archived), поиск, отметки, топики форумов;
  число сообщений подгружается по видимым строкам и кэшируется на время
  работы `serve`. Сохранение — `config.WriteTargets` (комментарии и прочие
  настройки сохраняются), перед записью — тот же отчёт, что в `setup` на `d`.
- **Архив — на отдельном порту (следующем, `8641`), то есть с другого
  origin:** в нём файлы, присланные другими людьми; HTML из чата, открытый
  там, не может прочитать страницы интерфейса (и токен) и вызвать API.
  Отдаются только `html/` и `media/` (`os.OpenRoot`: ни `..`, ни симлинки
  наружу); медиа, открытые отдельно, — с `CSP: sandbox`, всё кроме
  картинок, видео и звука скачивается (`Content-Disposition: attachment`).
  (Песочница для `html/` проверялась первой: встроенный браузер блокирует
  подзагрузки из opaque origin — отдельный origin надёжнее.)
- Все `/api/*`, включая GET, требуют токен: GET тоже имеют цену
  (соединение с Telegram, обход `media/`, проба `run.lock`).
  Подзагрузки интерфейса с других origin (`Sec-Fetch-Site`) запрещены.
- Соединение с Telegram открывается по требованию страницы чатов и
  закрывается после 5 минут простоя; список диалогов обновляется раз в 5
  минут; чаты из конфига, которых нет в списке, показываются с
  предупреждением.
- **Без фреймворков:** `html/template` + небольшой JS (`fetch`), стили — в духе
  архива; всё вшито в бинарник (`embed`), внешних запросов нет.
- `--open` открывает страницу в браузере. Автозапуск `serve` (launchd
  KeepAlive), значок в строке меню, доступ с телефона — вне этой итерации.

## 3. Страницы и API

| Путь | Что |
|---|---|
| `GET /` | Обзор: архив (сообщений, чатов, файлов, размер), последний запуск (когда, итог, ошибки), бэкапы по репозиториям (последний успешный), расписание (стоит ли, следующий запуск), бот (настроен ли), последние 20 запусков; кнопки «Обновить сейчас», «Открыть архив»; лог текущего запуска |
| `GET /chats` | Выбор чатов и топиков |
| `GET :8641/{html,media}/…` | Архив как сайт (отдельный origin) |
| `GET /api/status` | JSON для обзора (обновляется на странице раз в несколько секунд, пока идёт запуск) |
| `POST /api/run` | Запустить `tgbup run`; 409, если запуск уже идёт |
| `GET /api/run/log` | Хвост `run.log` (последние ~200 строк) |
| `GET /api/chats` | Группы, чаты (id, название, тип, выбран ли, исключённые топики) |
| `POST /api/chats/counts` | `{ids}` → число сообщений и топиков (кэш) |
| `GET /api/chats/{id}/topics` | Топики форума с числом сообщений |
| `POST /api/chats/preview` | Выбор → отчёт (как `sync --dry-run`) и текст конфига |
| `POST /api/chats` | Выбор → запись конфига |

## 4. Тесты

- Безопасность: чужой `Host` → 403; POST без токена или с неверным → 403;
  `/archive/archive.sqlite`, `/archive/files/…`, `/archive/html/../archive.sqlite` → 404.
- Обзор: из временного архива с записями `runs` и метками бэкапов.
- Запуск: фейковый запускатель — 202, второй во время работы — 409; лог —
  хвост файла.
- Чаты: фейковый источник диалогов — группы и выбор из конфига; сохранение
  пишет `include`/`exclude_topics` и сохраняет комментарии; пустой выбор → 400.
- `--listen` не на loopback → ошибка запуска.
