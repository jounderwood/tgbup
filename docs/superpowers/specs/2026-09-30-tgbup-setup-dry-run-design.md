# tgbup setup и sync --dry-run: дизайн

Дата: 2026-09-30
Статус: на ревью
Основа: `2026-09-28-tgbup-design.md` (выбор чатов §4–5, конфиг §4)

## 1. Цель

Сейчас выбор чатов задаётся руками в `config.yaml` (названия папок, `@username`,
числовые ID). Нужно:

- **`tgbup sync --dry-run`** — показать, что будет заархивировано, ничего не
  скачивая и не создавая архив;
- **`tgbup setup`** — выбрать чаты интерактивно, используя папки Telegram для
  навигации, и записать выбор в конфиг.

Критерий успеха: первый запуск на боевом аккаунте делается без ручного поиска ID
и без правки YAML, а перед выгрузкой видно, что именно и примерно сколько будет
скачано.

## 2. Решения

- **Выбор явный.** `setup` записывает в `targets` только `include` с числовыми
  ID. Папки — только навигация. Новые чаты, добавленные в папку позже, сами не
  подхватываются (напоминание о них — задача еженедельной сводки, план 3).
- **Интерфейс — нумерованные списки** в обычном терминале, без TUI и новых
  зависимостей; работает и по SSH на NAS.
- Ручная правка YAML (`folders`, `include`, `exclude`) остаётся поддержанной;
  `sync` понимает всё как раньше.

## 3. `tgbup sync --dry-run`

- Та же загрузка конфига, подключение и выбор чатов (`SelectTargets`,
  `AddMigrated`), что у `sync`; не берёт `run.lock`, не открывает и не создаёт
  `archive.sqlite`, ничего не скачивает.
- Для каждого чата — один запрос `messages.getHistory(limit=1)`; счётчик берётся
  из `count` ответа (`messages.messagesSlice` / `channelMessages`), для
  `messages.messages` — длина списка.
- Вывод:
  ```
  would archive 3 chats, ~20 332 messages:
    -1001234567890  forum    Семейный форум   folder Семья   ~4 812
    123456789       private  Мама             include        ~15 300
    -4567890        group    Дача             include        ~220
  warning: include @old_name: chat not found among your dialogs
  ```
- Код выхода: 0 без предупреждений; 1 при предупреждениях (ненайденный
  `include`) или ошибках; 2 при неверных флагах. `--takeout` вместе с
  `--dry-run` — ошибка флагов.
- Объём медиа не оценивается: Telegram не отдаёт размеры без полного прохода.

## 4. `tgbup setup`

Требует `tgbup login`. Загружает диалоги (`Dialogs`) и папки (`Folders`).

**Главный экран:**
```
Выбрано: 18 чатов
  1) Семья        (5 чатов, выбрано 3)
  2) Бизнес       (12, выбрано 12)
  3) Вне папок    (140, выбрано 2)
  4) Архив        (30, выбрано 1)
  s) поиск по названию    d) готово    q) выйти без сохранения
>
```
Номер открывает экран папки. «Вне папок» — диалоги, не попавшие ни в одну папку;
«Архив» — архивные диалоги.

**Экран папки / результатов поиска:**
```
Семья:
  1) [x] Семейный форум   forum
  2) [ ] Мама             private
  3) [x] Дача             group
номера (1,3,5-7) — переключить, a — все, n — ни одного, Enter — назад
>
```
- Ввод `1,3,5-7` переключает отметки; повторы и пробелы допустимы; номер вне
  списка или мусор → сообщение об ошибке, выбор не меняется.
- Поиск — подстрока без учёта регистра по названию и username по всем диалогам.

**Начальное состояние:** если конфиг есть — отмечены чаты, которые он сейчас
выбирает (через `folders`, `include`, `exclude`); иначе ничего.

**Завершение `d`:** dry-run по выбранным (таблица из §3), затем
`Записать в <путь> (N чатов)? [y/N]`. `y` → запись, иначе возврат в меню.
`q` или EOF — выход без изменений, код 0.

## 5. Запись конфига

- Правится только узел `targets` через дерево `yaml.v3`: `include` —
  последовательность числовых ID с комментарием-названием у каждого элемента;
  ключи `folders` и `exclude` удаляются. Остальные секции и комментарии в них
  сохраняются как есть.
- Конфига нет → создаётся из `config.Default()` с новым `targets`.
- Итог проходит `config.Load` (валидация) до записи; запись атомарна
  (временный файл в том же каталоге → rename), права 0600.

## 6. Компоненты

| Где | Что |
|---|---|
| `internal/selector` | Состояние выбора (множество ID), разбор ввода (`1,3,5-7`, `a`, `n`), группировка диалогов по папкам / «Вне папок» / «Архив», поиск. Без Telegram и терминала |
| `internal/config` | `WriteTargets(path string, ids []int64, titles map[int64]string) error` |
| `internal/tgclient` | `HistoryCount(ctx, peer) (int, error)` |
| `cmd/tgbup/setup.go` | Диалог (ввод/вывод) поверх `selector` |
| `cmd/tgbup/sync.go` | Флаг `--dry-run`, общая печать таблицы |

## 7. Тесты

- `selector`: разбор ввода (диапазоны, повторы, границы, мусор), переключение,
  `a`/`n`, группировка (чат в двух папках, вне папок, архив), поиск.
- `config.WriteTargets`: сохранение чужих секций и комментариев, удаление
  `folders`/`exclude`, создание нового файла, права 0600, результат проходит
  `Load`.
- `HistoryCount`: `messagesSlice`, `channelMessages`, `messages` через `tgmock`.
- Диалог `setup` целиком: скрипт ввода + фейковые диалоги/папки/счётчики, без
  Telegram; проверка итогового YAML и отказа от записи по `N`/`q`.
- e2e: `sync --dry-run` на fixture видит 3 чата с ненулевыми счётчиками и не
  создаёт `archive.sqlite`.

## 8. Вне области

TUI; выбор «папка целиком с автодобавлением»; оценка объёма медиа; настройка в
`setup` чего-либо кроме `targets`.
