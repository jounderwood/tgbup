# tgbup: медиа с человеческими именами, без `files/` — дизайн

Дата: 2026-10-03
Статус: реализован (по запросу «медиа может лежать в одном месте, просто с человеческим названием, а маппинг весь
через БД и HTML»; «имя файла стоит оставить, это очень полезно»)
Основа: `2026-10-01-tgbup-render-design.md` (`files/`), `2026-10-02-tgbup-backup-design.md` (снимок)

## 1. Цель

- Один экземпляр каждого файла, сразу с понятным именем. Прослойки `files/` (жёсткие ссылки) больше нет.
- Связь «файл ↔ чат, топик, сообщение» живёт только в базе (`media.local_path`, `message_media`) и в страницах.
- Бэкап читается без tgbup: в снимок входит и `html/`.

## 2. Раскладка

```
media/<год>/<ГГГГ-ММ-ДД>_<ЧЧММСС>_<имя>.<расш>

media/2025/2025-06-14_180233_Договор аренды.pdf
media/2025/2025-06-14_180233_Договор аренды (2).pdf   совпадение
media/2025/2025-06-14_180240_Family.jpg               имени нет: чат
media/2025/2025-06-14_180301_VID_20250614.mp4
media/2025/2025-06-14_180510_Mom.ogg
```

- Только папка года: виды вперемешку, по имени — хронология. Вид файла знает база (`media.kind`).
- Дата и время — сообщения, через которое файл скачан (первая ссылка), в часовом поясе Mac в момент скачивания.
  Префикс без пробелов и двоеточий (двоеточие Finder показывает как `/`); сортировка по имени — хронологическая.
- `<имя>` — **оригинальное имя файла** из Telegram (`DocumentAttributeFilename`, уже хранится в `media.file_name`),
  с его пробелами и регистром. Есть у документов всегда, у видео/аудио/gif часто; у фото, голосовых, кружков и
  стикеров нет — тогда название чата на момент скачивания.
- Пересланный в несколько чатов файл лежит один раз; имя — по первому сообщению.
- Время изменения файла = дата сообщения.
- Имя задаётся при скачивании и потом не меняется (переименование чата ничего не двигает).

## 3. Что меняется в оригинальном имени (только безопасность)

- убираются `/ \ : * ? " < > |`, управляющие символы, ведущие точки (`..`, скрытые файлы);
- длина — до предела macOS (255 байт на имя), обрезается имя, не расширение;
- расширение: из имени, если оно безопасное; исполняемым (`.command`, `.sh`, `.app`, `.pkg`, `.dmg`, `.jar`,
  `.scpt`…) дописывается `.txt`; нет расширения — по MIME или виду, как раньше;
- чужим файлам ставится атрибут карантина macOS (`com.apple.quarantine`), как при загрузке браузером: при запуске
  из Finder macOS спросит подтверждение. Свои — отправленные самим владельцем аккаунта и не пересланные (в том
  числе Избранное) — без карантина. Чужой файл, пересланный владельцем, — чужой.

## 4. Выбор имени

Имя фиксируется в базе до скачивания: в `media.local_path` пишется свободный путь (статус остаётся `pending`),
затем скачивание в `<путь>.part` и переименование. Свободный — нет в базе у другого файла (уникальный ключ пути
без учёта регистра и нормализации Unicode, как сравнивает APFS) и нет на диске. Совпадение → ` (2)`, ` (3)` перед
расширением. Повторный запуск продолжает в тот же путь. Существующий файл не перезаписывается никогда.

## 5. Переезд существующего архива

Не делается (решение пользователя: архив выкачивается заново). Миграция базы 007 добавляет ключ пути и уникальный
индекс; файлы со старыми путями `media/<вид>/<id>` остаются рабочими — путь берётся из базы.

## 6. Бэкап

В снимок добавляется `html/`; `md/` — нет (то же содержание). Восстановление в tgbup по-прежнему перерисовывает
страницы; `html/` в снимке — для чтения после обычного `restic restore`.

## 7. Что убирается и что теряется

- `tgbup files`, пакет `browse` (функции имён остаются в отдельном пакете), `files/` в отчётах и документах.
- Раскладки по папкам чатов в Finder нет; вместо неё — `html/media.html` (фильтры по чату, топику, периоду, виду)
  и название чата в имени файлов без собственного имени.
- Одинаковые файлы, отправленные отдельно (не пересылкой), по-прежнему две копии на диске (restic в бэкапе хранит
  одну). Отдельная задача.

## 8. Тесты

- Карантин: чужой файл, свой, свой пересланный.
- Имя: префикс, оригинальное имя с пробелами и регистром, имя по чату, очистка, длина в байтах, исполняемые
  расширения, совпадения (в том числе по регистру и нормализации), не перезаписывает чужой файл на диске.
- Скачивание продолжает в записанный путь; время файла — дата сообщения.
- Бэкап: `html/` в снимке.
- e2e: файлы ищутся в `media/`.

## Решения обсуждения

- Оригинальное имя файла сохраняется; префикс даты у всех; префикс без пробелов и дефисов во времени.
- Только папка года, без папки вида.
- Карантин только для чужих файлов.

## По итогам ревью (2026-10-03)

- Файл скачивается во временный `.<имя>.part` (точка впереди: настоящие имена начинаются с даты, совпасть не
  могут); имя оставляет место под него в 255 байтах. restic исключает `.*.part`, а не `*.part`.
- Ключ имени — полное приведение регистра (`ß` = `ss`, `ﬁ` = `fi`) и нормализация, как в APFS.
- Файл другого размера на зарезервированном имени не считается своим: он остаётся, файл получает другое имя.
- Карантин: ошибка записи атрибута — предупреждение в журнале, не ошибка файла; файлы через inline-бота — чужие.
  Добавлены образы дисков и файлы-ссылки macOS в список запускаемых расширений.
- `forget` группирует снимки по хосту и тегу: с добавлением `html/` набор путей меняется, а группа по путям
  никогда бы не прореживалась.
- Восстановление: файл с тем же именем, но другим содержимым, переносится в `media.before-restore-<время>`;
  при копировании между томами сохраняются дата и карантин.
- 2026-10-04: по уточнению пользователя («по году, а потом по типу») — `media/<год>/<вид>/…`, вид: photo, video, file,
  voice, round, audio, sticker, gif. Файлы, скачанные раньше, остаются на своих путях (путь в базе).
