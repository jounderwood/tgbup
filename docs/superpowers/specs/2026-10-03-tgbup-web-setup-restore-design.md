# tgbup: настройка через веб-страницу и восстановление из бэкапа — дизайн

Дата: 2026-10-03
Статус: реализован (по запросу «засетапить через веб» и «восстановление через restic не гуманно, в туле должно быть
всё»); проверка пользователем впереди
Основа: `2026-10-03-tgbup-init-design.md` (шаги мастера), `2026-10-03-tgbup-serve-design.md` (страница,
защита), `2026-10-02-tgbup-backup-design.md` (снимки)

## 1. Цель

- Всю настройку после сборки можно пройти в браузере: `make setup` открывает страницу мастера.
  Мастер в терминале (`tgbup init`) остаётся.
- Восстановить архив из бэкапа можно без ручного restic: командой `tgbup restore`, вопросом в начале
  `tgbup init` и на странице мастера.

## 2. Решения

- **Одни шаги для терминала и страницы.** Проверки «сделано ли» и действия (записать ключи, папку, бэкап,
  бота, поставить расписание) отделяются от ввода-вывода (`cmd/tgbup/steps.go`); `init.go` спрашивает в
  терминале и вызывает их, веб-бэкенд вызывает их из обработчиков. Отдельным пакетом это не стало: шаги
  опираются на оркестрацию в `cmd/tgbup` (загрузка конфига, бэкап, launchd); вынос — вместе с ней, позже.
- **Вход в Telegram на странице — телефон → код → пароль 2FA**, по шагам gotd (`SendCode`, `SignIn`,
  `Password`); соединение держится между запросами. QR-входа нет.
- **Страница мастера `/setup`** — карточки шагов со статусом и формой. `serve --open` и `make setup`
  открывают её, пока не сделаны обязательные шаги; иначе — обзор. Вкладка «Setup» есть всегда (смена
  настроек).
- **Выбор папки** — кнопка «Choose…»: браузер не отдаёт полный путь, поэтому окно выбора папки macOS
  открывает сам tgbup (`osascript … choose folder`); путь можно и вписать.
- **Пароль бэкапа** в браузере: сгенерированный показывается один раз с кнопкой «Copy», сохранение
  только после галочки «I saved it in my password manager»; или ввод своего/прежнего дважды.
- **Долгие действия** (создание репозиториев, вход в Google Drive, первая выгрузка, проверочный запуск) —
  на странице видно, что идёт работа; выгрузка и проверочный запуск — отдельный процесс с журналом, как
  «Update now».
- **Восстановление** — в `internal/backup`: список снимков (`restic snapshots --json --tag tgbup`),
  восстановление снимка во временную папку рядом с архивом (`restic restore`) и перенос на место
  переименованием (без второй копии медиа):
  - `archive.sqlite` → в папку архива; если там уже есть база, она переименовывается в
    `archive.sqlite.before-restore-<время>`, ничего не удаляется;
  - `media/` → в папку архива; уже существующие файлы остаются, недостающие переносятся;
  - `config.yaml` из снимка записывается, только если конфига ещё нет; `archive_dir` в нём заменяется
    на выбранную папку; место, из которого восстановили, добавляется в `backup.repositories`;
  - пароль, которым снимок открылся, сохраняется в `secrets.env`;
  - затем пересборка `files/` и `tgbup render --full`.
  Восстановление идёт под `run.lock`. Google Drive через rclone на новом Mac — подключение тем же
  `rclone config create` (вход в браузере), если удалённого хранилища нет.
- **`tgbup restore`**: `--from <место>` (иначе — первое из конфига или вопрос), `--snapshot <id|latest>`,
  `--list` — только показать снимки; пароль — из `RESTIC_PASSWORD`/`secrets.env` или скрытым вводом.
- **В `tgbup init`** шаг «Archive folder» при отсутствии конфига спрашивает «New archive or restore from a
  backup? [N/r]».

## 3. Страница мастера

| Шаг | Состояние | Форма |
|---|---|---|
| Telegram API keys | есть оба ключа | api_id, api_hash; ссылка на my.telegram.org |
| Telegram login | сессия авторизована | телефон → код → пароль 2FA (если нужен) |
| Archive | конфиг есть | «New archive»: папка (+Choose…); «Restore from a backup»: место, пароль, снимок |
| Chats | есть `targets` | ссылка на страницу Chats |
| Backups | места + пароль | вкл/выкл, папка на этом Mac, доп. места галочками, свой путь, пароль |
| Alerts bot | токен и chat_id | токен → «напишите боту» → выбор чата → тестовое сообщение |
| First download | в архиве есть сообщения | «Start» (takeout), «Without takeout»; журнал |
| Schedule | задача стоит | «Install», «Run a check now» и итог |

Шаг PATH на странице не нужен. При `TGBUP_TEST_DC=1` шаг расписания недоступен.

## 4. API (все запросы — с токеном, см. serve)

`GET /api/setup` — состояние шагов и данные для форм (найденные места бэкапа, текущие значения, без
секретов). `POST /api/setup/keys`, `/login/code`, `/login/signin`, `/login/password`, `/archive`,
`/choose-folder`, `/backup`, `/password/new`, `/bot/check`, `/bot/wait`, `/bot/save`, `/download`,
`/schedule`, `/schedule/check`, `/restore/snapshots`, `/restore`. Ошибки ввода — 400 с понятным текстом.

## 5. Тесты

- `backup`: список снимков и восстановление с настоящим restic (skip без него): база, медиа, конфиг на
  месте; существующая база не затирается; существующие медиа не трогаются.
- Шаги: ключи (проверка), папка, бэкап (пароль только с подтверждением), бот — общие для CLI и веба.
- Веб: вход по шагам с фейковым Telegram (код, 2FA, неверный код), все `POST` без токена — 403, ответы
  без секретов (кроме только что сгенерированного пароля).
- `tgbup restore --list`/восстановление; `init` с выбором «restore».

## Расхождения с реализацией (2026-10-03)

- Шаг бэкапа на странице можно пройти до выбора чатов; создание репозиториев их не требует. Папка-репозиторий
  считается сделанной, только когда restic её создал (`<папка>/config`).
- `make setup` открывает страницу, `make setup-cli` — `tgbup init`.
- В тестовом режиме без конфига папка архива по умолчанию — `<папка тестового конфига>/TelegramArchive`.
- Вход по телефону проверен тестом с поддельным Telegram (код, 2FA, неверный код, повторная отправка кода), но не вживую; бот — не вживую (нужны код и сообщение пользователя).
- По итогам ревью: пароль снимка сохраняется при восстановлении, только если своего ещё нет; если в работе другой
  пароль, он остаётся, а место восстановления не добавляется в бэкапы. Конфиг из снимка принимается, если в
  текущем нет чатов (места бэкапа из обоих объединяются); конфиг с чатами не меняется, `archive_dir` тоже.
  Новый пароль, заменяющий рабочий, сначала проверяется на существующих репозиториях. Медиа на другом томе
  копируются; при сбое после замены базы ошибка называет, где прежняя. Шаги входа выполняются по одному,
  брошенный вход закрывается через 10 минут. Вывод `rclone config create` (в нём токен Google) не показывается.
- Тестовый режим требует своих `TGBUP_CONFIG`, `TGBUP_SECRETS`, `TGBUP_STATE_DIR` (кроме `login`); тестовый
  конфиг пишется сразу с папкой архива рядом с ним; папка бэкапа по умолчанию — тоже рядом; e2e работает с
  копиями сессии и ключей.
