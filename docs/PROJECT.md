# tgbup

Автономный архив Telegram-чатов, групп и форумов: выгрузка 4 раза в сутки, чтение в браузере и Obsidian,
бэкапы restic. Этот файл — актуальное устройство и журнал решений; спеки в `superpowers/specs/` — решения на
момент их принятия, расхождения с реализацией перечислены в конце каждой.

## Как устроено

### Подсистемы

| Пакет | Отвечает за | Не делает |
|---|---|---|
| `config` | `config.yaml`, `secrets.env`, пути (XDG, `TGBUP_*`); правка конфига с сохранением комментариев | не ходит в сеть |
| `tgclient` | соединение с Telegram (gotd): вход, takeout, диалоги и папки, история, файлы; flood wait, rate limit | ничего не пишет на диск, кроме сессии |
| `selector` | какие чаты архивировать: папки, `include`/`exclude`, исключённые топики, группы и поиск для `setup` | без Telegram и терминала |
| `syncer` | инкрементальная выгрузка: курсоры по чатам, пачка + курсор одной транзакцией, закрепы, фильтр топиков, недоступные чаты | не качает файлы |
| `convert` | сообщение Telegram → строка базы, медиа и метаданные (`meta_json`) | без ввода-вывода |
| `store` | `archive.sqlite`: схема и миграции, сообщения, очередь медиа, отпечатки страниц, `runs`, `meta` | — |
| `media` | очередь файлов: потоки, докачка `.part`, попытки (5), тайм-аут куска (2 мин), правила пропуска → `media/` | не трогает сообщения |
| `browse` | `files/` — медиа по чатам и топикам с понятными именами, жёсткими ссылками | — |
| `render` | `html/` и `md/` из базы: страницы по 500 сообщений, календарь, поиск, раздел «Медиа»; только изменившиеся страницы | не ходит в Telegram |
| `stats` | подсчёты для `dry-run`, `setup` и веб-страницы | ничего не пишет |
| `backup` | `integrity_check` → `VACUUM INTO` → снимок restic в каждое место → `forget`, по расписанию `prune` и `check` | не знает про Telegram |
| `deps` | restic и rclone закреплённых версий: поиск или скачивание с проверкой SHA-256 | — |
| `notify` | бот: ошибки сразу, сводка раз в `summary_every`; проверка токена, поиск chat_id | — |
| `serve` | веб-страница: обзор, «Update now», выбор чатов, архив на отдельном origin | логику берёт из `cmd/tgbup` через `Backend` |
| `cmd/tgbup` | команды; мастер `init`; порядок шагов `run`; `run.lock`; задача launchd | — |

### Что где лежит

```
~/.config/tgbup/config.yaml        что архивировать, папка архива, места бэкапа          → в снимке (копия)
~/.config/tgbup/secrets.env (600)  TG_API_ID/HASH, RESTIC_PASSWORD, BOT_TOKEN/CHAT_ID         → не в снимке
~/.config/rclone/rclone.conf       вход в Google Drive через rclone (если выбран)             → не в снимке
~/.local/state/tgbup/
  session, session-test            вход в Telegram (боевой и тестовые серверы)                → не в снимке
  run.lock                         один запуск за раз (sync, backup, run, render, files)
  bin/restic-*/, bin/rclone-*/     скачанные зависимости
  backup/archive.sqlite, config.yaml   копия базы и конфига для снимка                       → в снимке
  logs/run.log                     вывод запусков по расписанию и из веб-страницы
<archive_dir> (~/TelegramArchive)
  archive.sqlite                   источник правды: сообщения, чаты, очередь медиа, история запусков,
                                   отпечатки страниц, отметки бэкапов
  media/<тип>/<id>.<ext>           файлы, один на все пересылки                               → в снимке
  html/  md/  files/               производные: пересобираются из базы и media/              → не в снимке
<места бэкапа>                     репозитории restic; по умолчанию ~/TelegramBackup,
                                   дополнительно iCloud, Google Drive, внешние диски и любые restic-репозитории
~/Library/LaunchAgents/com.gitlab.joeunderwood.tgbup.plist   tgbup run в 00:30, 06:30, 12:30, 18:30
```

### Сценарии

- **Выгрузка** (`tgbup run`; его запускают расписание и «Update now»): `run.lock` → выбор чатов → `syncer` пишет
  сообщения в базу → `media` качает файлы → `browse` пересобирает `files/` → `render` перерисовывает изменившиеся
  страницы → `backup` во все места (даже если выгрузка упала) → запись в `runs` → бот (ошибки сразу, сводка по
  интервалу). `files/` и рендер выполняются и после потери сессии: им не нужен Telegram.
- **Просмотр:** `html/index.html` с диска или через `tgbup serve` (архив на `:8641`); `md/` в Obsidian; `files/` в
  Finder; обзор `serve` читает `runs` и отметки бэкапов из базы.
- **Бэкап:** снимок = копия базы через `VACUUM INTO` + копия `config.yaml` + `media/`. Без пароля restic снимки
  не прочитать, поэтому мастер всегда показывает пароль и ждёт подтверждения, что он сохранён.
- **Восстановление:** `restic restore` → `archive.sqlite` и `media/` в папку архива, `config.yaml` на место →
  `tgbup login` → `tgbup render` и `tgbup files` пересоберут просмотр.

### Рендер и бэкап

Рендер — производная часть, бэкап хранит исходные данные: `html/`, `md/` и `files/` в снимок не входят и
целиком восстанавливаются из базы и `media/`. В запуске рендер идёт до бэкапа, но бэкап от него не зависит.
Единственное общее — отпечатки страниц (`render_pages`) лежат в базе и попадают в снимок; поэтому страница
пропускается, только если и отпечаток совпал, и её файлы существуют (иначе после восстановления ничего не
перерисовалось бы). Страницы ссылаются на `media/` относительными путями, поэтому восстановленный архив после
`tgbup render` показывает и файлы.

## Decisions log

### 2026-09-28 — Go + gotd/td, своя тула
- **Альтернативы:** `tdl` как внешний бинарник (AGPL-3.0; экспорт пропускает служебные сообщения, по умолчанию только медиа, один чат за вызов); форк `tg-archive` (одна группа, нет топиков/закрепов); Python + Telethon.
- **Почему:** нужны все типы сообщений, закрепы, скрытые ссылки и топики — готовые тулы этого не дают; Go даёт один бинарник для Mac и будущего NAS; gotd/td — MIT.

### 2026-09-28 — SQLite как источник правды, представления генерируются
- **Альтернативы:** JSONL-файлы; только HTML/Markdown.
- **Почему:** атомарные транзакции (пачка + курсор), простые обновления (закрепы, статус медиа); HTML/MD перегенерируются без повторной выкачки. Риски (синхронизация живого файла, SMB/NFS) закрыты: БД только на локальном диске, в облако — снимки restic.

### 2026-09-28 — restic в два репозитория (iCloud + Google Drive через rclone)
- **Альтернативы:** синхронизация архива в iCloud без версий; внешний диск; один облачный репозиторий.
- **Почему:** шифрование на клиенте (бизнес-данные), дедупликация, версии и retention; два провайдера — 3-2-1; смена бэкенда — строка конфига + `restic copy`.

### 2026-09-28 — Без привязки к macOS
- **Альтернативы:** Keychain для секретов.
- **Почему:** планируется переезд на NAS; секреты в `secrets.env` (chmod 600) / `*_FILE`, пути XDG.

### 2026-09-29 — Таблица `peers` (миграция 002) и правки по итогам ревью ядра
- **Альтернативы:** класть имена источников пересылок в `chats`; не хранить их вовсе.
- **Почему:** в `chats` они попали бы под пометку «недоступен» и в уведомления; без хранения «переслано от» показывает только ID, а access hash для дозапроса не сохраняется. Там же: медиа-задача берёт чат и сообщение из одной ссылки; ошибки диска не сжигают попытки; `skipped` пересматривается при смене конфига; диалоги без дублей архива; удалённые аккаунты остаются; ненайденный `include` и «застрявшая» выгрузка вперёд — явные ошибки.

### 2026-09-28 — Вне v1
MCP и команды боту, FTS5-поиск, транскрибация, восстановление в Telegram, Docker/NAS, отслеживание правок/удалений.
Позже из этого списка вне области по-прежнему всё; веб-интерфейс (`serve`) сделан 2026-10-03.

### 2026-10-03 — Настройка одной командой `tgbup init`
- **Альтернативы:** README-инструкция из ~10 ручных шагов (было); отдельные команды с подсказками «что дальше»; установщик `curl | sh` из релизов.
- **Почему:** повторяемый мастер с проверкой каждого шага даёт и первую настройку, и продолжение после прерывания, и смену чатов/хранилищ, без правки файлов. Пароль restic генерируется и не записывается, пока человек не подтвердит, что сохранил его вне Mac; chat_id бота берётся из `getUpdates`; Google Drive подключается `rclone config create … scope=drive.file`. Ввод читается по запросу, а не фоном: иначе фоновое чтение забирало строки у входа в Telegram и скрытого пароля 2FA. `curl | sh` отложен — репозиторий приватный, `make setup` требует только Go.

### 2026-10-03 — `tgbup serve`: веб-страница только для этого компьютера
- **Альтернативы:** десктоп-приложение (Wails/Tauri); доступ из локальной сети или с телефона; запуск «Update now» внутри процесса `serve`.
- **Почему:** страница в браузере не требует сборки под каждую ОС и годится для будущего NAS. Слушает только loopback: архив личный, а входа нет. От чужих страниц защищают проверка `Host` (DNS rebinding), токен процесса в заголовке каждого запроса к API и CSP. Архив отдаётся с отдельного origin (следующий порт): в нём файлы, присланные другими людьми, и HTML среди них не должен читать страницу управления (песочница `CSP: sandbox` для `html/` отвергнута: встроенный браузер блокирует подзагрузки из opaque origin). «Update now» запускает отдельный процесс `tgbup run` с выводом в `run.log`, так что запуск не обрывается вместе со страницей и не отличается от планового. Проверка «идёт ли запуск» на мгновение берёт `run.lock`, поэтому `acquireLock` ждёт до 2 с, прежде чем пропустить запуск.

### 2026-10-03 — Бэкап по умолчанию в папку на этом Mac, облака — дополнительно
- **Альтернативы:** только облака (было); бэкап выключен по умолчанию; пароль без участия человека, пока копии на этом диске.
- **Почему:** версии архива защищают от удалений и ошибок и без облака; первый бэкап не должен требовать входа куда-либо. Каждый запуск делает снимок во все выбранные места. Пароль всегда показывается и подтверждается: потерянный пароль делает нечитаемыми все копии, а «тихий» пароль пользователь отверг.

### 2026-10-03 — Тайм-аут на кусок файла
- **Альтернативы:** общий тайм-аут запуска; без тайм-аута (было).
- **Почему:** gotd без ограничения ждёт соединения с дата-центром файла; зависший запуск держал бы `run.lock`, и все плановые запуски молча пропускались бы. 2 минуты на кусок 512 КБ; тайм-аут — неудачная попытка, после 5 файл помечается `failed`.
